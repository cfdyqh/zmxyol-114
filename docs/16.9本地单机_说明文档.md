# 造梦西游OL 16.9 本地单机版 · 使用与架构说明

> 整理时间：2026-11-09
> 运行目录：`接手材料\运行包\ZXMY-MuMu-Test`
> 客户端：MuMu 模拟器（Android 12 x86_64）里的 **原版 16.9 客户端**（`org.yjmobile.zmxy`，versionCode 1650）

---

## 一、它是什么

不是"魔改客户端"，而是**原版客户端 + 本地服务**的组合：

```
┌─────────────────────────┐        ┌──────────────────────────────┐
│  MuMu 模拟器             │        │  Windows 主机                 │
│  org.yjmobile.zmxy      │  ADB   │  ZXMY-MuMu-Test              │
│  原版 16.9 客户端        │◄──────►│  ├ launcher.py  (启动/停止/GM) │
│  + 官方热更库 1650_7     │  网络   │  ├ flowlab/     (Python 服务) │
│       _64_game.so       │◄──────►│  │   └ gateway :19653         │
└─────────────────────────┘ 10.0.2.2└──────────────────────────────┘
```

- **游戏本体是官方的**（签名、资源、逻辑都没改）；
- 只有**热更的原生库**被替换成随包提供的官方 ARM64 库（`1650_7_64_game.so`）；
- 所有协议请求被网关接管，用**抓取到的官服应答模板（fixtures）**回放，再叠加本地合成的副本/邮件/装备等逻辑；
- 因此**不需要改服务器、不需要改 APK**，也不碰角色存档以外的任何系统。

## 三、启动 / 停止

### 图形方式（推荐）

1. 双击 **`本地服务启动器.exe`**；
2. 填 **MuMu 该实例的 ADB 端口**（`config.json` 里默认 `127.0.0.1:16384`）；
3. 点 **启动服务**。

启动器会自动：

1. 检查 ADB 设备与已安装 APK 版本；
2. 按版本把对应原生库（1650 或 1640）部署到
   `/data/user/0/org.yjmobile.zmxy/app_libs/`（原库备份到 `.zxmy_native_backups`）；
3. 配置路由，让模拟器把游戏请求发到主机 `10.0.2.2:19653`；
4. 启动网关与 GM。

### 命令行方式

```bat
runtime\python.exe -X utf8 launcher.py start      :: 启动
runtime\python.exe -X utf8 launcher.py stop       :: 停止（等缓存/路由恢复后再关模拟器）
runtime\python.exe -X utf8 launcher.py check      :: 环境检查
runtime\python.exe -X utf8 launcher.py gm         :: 打开 GM 控制台
runtime\python.exe -X utf8 launcher.py backup     :: 备份当前存档
runtime\python.exe -X utf8 launcher.py restore <zip>  :: 还原
runtime\python.exe -X utf8 launcher.py adb-check  :: ADB 诊断
```

## 四、网络与协议

| 项 | 值 |
|---|---|
| 网关监听 | `0.0.0.0:19653`（`gateway.py` 里 `asyncio.start_server(..., 19653)`） |
| 模拟器访问主机 | `10.0.2.2`（MuMu NAT 里指向宿主机） |
| ADB 序列号 | `config.json.adb_serial`，默认 `127.0.0.1:16384` |
| MuMu 端口候选 | 7555 / 16384 / 16416 / 16448 / 16480 |
| 额外目标 IP | `171.43.195.184`、`120.53.205.157`（官服 CDN/SDK 地址，重定向到本地） |

请求流程：

```
客户端 → (路由劫持到 10.0.2.2:19653) → gateway.py
        → zmxy_api.decrypt_request（3DES 解密请求）
        → 按 action 分发：
            · fixtures 里有的 → 原样回放（可局部改写）
            · 副本/背包/邮件/装备 → 本地模块合成应答
        → zmxy_api.encrypt_response → 回给客户端
```

**抓到的应答模板只有 18 份**，其余（副本、邮件、装备、灵物等）都是本地按协议结构合成的。

## 五、数据、存档与备份

| 内容 | 位置 |
|---|---|
| 当前进度 | `data/state.sqlite3` + `data/roles/223/` |
| 当前会话 | `data/current.json`（模式 `replay`、控制器 PID、ADB 序列号） |
| 每次启动日志 | `logs/<YYYYMMDD_HHMMSS_mmmmmm>/` |
| 关键日志文件 | `events.jsonl`（请求/事件流）、`result.json`、`retargets.jsonl`（路由重定向）、`routing.json`、`preflight.json`（环境检查） |
| 自动备份 | `backups/auto_<时间戳>/`（启动前自动做） |
| 手动备份 | `备份当前存档.bat` 或 `launcher.py backup` |

迁移目录时：**先停止服务 → 关闭 GM → 连 `data` 一起复制**。

## 六、GM 控制台（`launcher.py gm`）

窗口页签：

| 页签 | 功能 |
|---|---|
| 发邮件 | 选物品（来自 `item_catalog.json`）+ 数量，发到游戏邮箱 |
| 邮件记录 | 已发/已领列表（SQLite `local_mail` 表） |
| 等级与货币 | 角色等级、点券、绑定点券等 |
| 装备管理 | 按 `equipment.py` 的字段表编辑（生命/魔法/攻击/防御/幸运/回血/回魔/魔抗/闪避/暴击/命中/抗暴/增伤/减伤/魔攻；至尊装备另有 `BE` 显示品质 / `CC` 星级 / `CF` 品级） |
| 灵物与本命神 | 灵物、本命神培养数据 |
| 被动技能 | 被动技能等级 |
| 修复解锁 / 跳过教程 | 一键修复解锁状态、跳过新手引导 |

所有 GM 操作**只改本地存档**，不发外网请求。

## 七、随包的关键数据

| 文件 | 说明 |
|---|---|
| `flowlab/fixtures/*.json`（18 份） | 官服真实应答：登录、roledata2（含 112 个配置块）、邮件、副本列表等 |
| `flowlab/item_catalog.json` | 物品目录（邮件/装备管理用，含来源表标记，如 `noblest_equip`） |
| `flowlab/dungeon_catalog.json` | 副本目录（如 `100056 八仙过海` 的子关卡 700171/700172/700173/700201~700210） |
| `flowlab/client_libraries/*.so` | 官方 ARM64 热更库（1640 / 1650），部署时校验 MD5 |

原生库对照：

```
1640_10_64_game.so   MD5 1d5f4bd37b2d6b55f786d4d37830737f   （16.8.2 / versionCode 1640）
1650_7_64_game.so    MD5 030a84272d160545cebc51f5cbf22eae   （16.9.0 / versionCode 1650）
```

**不能在 16.9 里强放 1640 的库**，启动器会按 APK 版本自动选。

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 启动器报"设备离线" | MuMu 的 ADB 调试被关，或实例重启过；在 MuMu 里重开 ADB 调试，或重启实例 |
| 卡在"检查更新" | 网关没起来或端口被占（19653）；检查 `logs/<最新>/events.jsonl` 与 `启动错误.log` |
| 端口填错 | MuMu 多开时每个实例端口不同，用 `MuMuManager.exe adb -v <实例号>` 查 |
| 想换 16.8.2 玩 | 启动器会按安装包版本号自动部署 1640 库，无需手动换 |
| 想还原旧进度 | 先停服务与 GM，再 `launcher.py restore <备份zip>` |
| 修改过 Python 代码 | 需重新生成"文件校验.json"（`文件校验.json` 记录了每个文件哈希） |

## 九、与 11.4 单机版的区别（容易混）

| 项 | 16.9 本地单机（本文档） | 11.4 单机（`v11/`） |
|---|---|---|
| 客户端 | **原版** 16.9 APK（MuMu 里） | 自己打的 `fixXX.apk`（反 Legu） |
| 改造点 | 只换官方热更库 + 劫持协议 | 改 APK：换 `libtprt.so` 壳、解密 `libgame.so`、内置 Java 服务器 |
| 服务端 | Windows 上的 Python 网关（`flowlab`） | APK 内的 `LocalServer.java`（本地 socket） |
| 数据来源 | 18 份 fixtures + 本地合成 | 全部本地 `.sdb` + Java 逻辑 |
| 稳定度 | 高（原版客户端） | 一般（模拟器 houdini / 手机音频会崩） |
| 功能完整度 | 官方有的都有（真灵/至尊/传承全在） | 真灵缺失、传承比例缺失、邮件面板空 |
| 适合 | 正常游玩、体验完整版本 | 研究 11.4 老版本、离线收藏 |

**结论**：想玩得完整、稳定 → 用 **16.9 本地单机**；想研究 11.4 老版本 → 用 `v11` 那套。
