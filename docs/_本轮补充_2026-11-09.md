# 2026-11-09 第三轮（暴击 / 存档 / 多存档）

最新包：`v11\build\fix172.apk`（716.5 MB，已签名，已装到雷电9 实测）

## 1. 暴击伤害 ≈ 0（已修）

**根因（客户端计算问题，不是属性问题）**

`YJRoleBullet` 命中后的暴击分支在 `libgame` 里是这样的（ARM，VA 0x13e9c4c）：

```
13e9c4c  add r0, r6, #0x590    ; A = bullet.critFactor
13e9c50  add r0, r0, #4
13e9c54  bl  0x65768c          ; 读 A
13e9c58  mov r1, r0
13e9c5c  mov r0, r4
13e9c60  bl  0x1aa06fc         ; r4 = damage * A  (__aeabi_fmul)
13e9c64  mov r1, #0
13e9c68  mov r4, r0
13e9c6c  bl  0x1aa0adc
13e9c70  cmp r0, #0
13e9c74  beq 0x13e9248
13e9c78  ...                   ; + B
13e9c94  b   0x13e9248
```

A / B 来自角色聚合出来的 `critical_damage`（`YJRole::getCriticalDamage` @0x13480bc，
它把各个属性来源对象 `+0xa4` 的浮点加起来）。本机这个和是 0，于是
**暴击伤害 = 普通伤害 × 0 ≈ 0**（面板里「暴伤 0」就是这个值）。

**为什么不能直接改 .so**

`libgame` 会校验自己的 .text：只要 `libgame.so` 有一个字节和原版不同，
启动就弹「更新检查失败, 请勿使用破解版进行游戏(3)」或者直接 SIGSEGV
（实测：把 .text 末尾 4 字节改成 NOP 也一样崩）。所以文件必须保持逐字节原样。

**修法：运行时内存补丁（改 libtprt 垫片）**

`native/tprt_shim.c` 本来就是我们自己写的壳（替掉乐固 libtprt），它已经有
`libgame_base()` + `mprotect` + 全内存扫描的 urlpatch 线程。这轮给它加了一个
`patch_crit_damage()`：等 libgame 加载完，把上面那段尾巴改写成

```
ldr r1,[pc,#12] ; 1.5f
mov r0,r4
bl  __aeabi_fmul
mov r4,r0
b   0x13e9248
.word 1.5f
```

也就是 **暴击 = 普通伤害 × 1.5**。改倍率只要跑
`python _mk_shim_crit.py 2.0`（1.5/1.75/2.0 都行）再重打包。

- 生成脚本：`v11\_mk_shim_crit.py`（注入 + 用 NDK r26 编译成 `native/libtprt-crit.so`）
- 打进包里的位置：`lib/armeabi/libtprt.so`
- 生效标记：`/sdcard/yj/critpatch_ok`

## 2. 存档：登录界面显示 Lv 1 / 每次登录被压回 1 级（已修）

`/sdcard/yj/login.json` 和 `login_enterserver.json` 是**形状模板**（不能删，删了原生崩），
但里面的数值是「新建角色的 1 级数据」：

```
"rolelist": {"1":[{"rid":"1001","rolelv":"1",...}]}
"savedata": {"roledata":{"role":{"rolelv":"1","attribute":{"hp":"80",...}}}}
```

以前这两个文件被**原样发出去**，于是登录界面永远 Lv 1，客户端还会拿这个等级同步存档。
本轮在 `LocalServer.personalizeLogin()` 里把模板当形状用、数值换成真实存档：

- `rolelist` 里那一个角色的 `rid/username/rolelv` → 当前激活角色的真实值
- `savedata` → 模板 ∩ 真实存档（`mergeObject`，存档优先）
- `rid / lastrid / cur_role_id / lastdata / service` → 与当前角色一致

实测：登录界面显示 `玩家 Lv 90`（以前是 Lv 1）。

## 3. 多存档：新建的角色退出就没了（已修）

**根因**：`ensurePresetRoles()` 里有一段 `if (true) { ... return; }`，为了绕开
「多角色进游戏崩」会把 `roles.json` **裁剪到只剩第一个角色**，并把多余存档删掉。
所以新角色一退出登录就被删。

**现在的做法**

1. 不再裁剪；`roles.json` 里的角色全部保留，每个角色独立 `savedata_<rid>.json` +
   `profile_<rid>.json`（缺存档时用登录模板补一份完整 1 级的，避免空档崩）。
2. **登录时只下发当前激活的那一个角色**（固定挂在 serverId=1）。
   实测 11.4 客户端只要 rolelist 里出现第 2 个角色、或者出现 serverId≠1 的键，
   登录场景就在 GL 线程 SIGSEGV（`fault addr 0x10`），所以不能一次给多个。
3. 换角色：左上角新增悬浮按钮 **「切换角色」**（`SkipButton.cycle()` →
   `LocalServer.cycleRole()`），点一下把 `lastrid.txt` 换成下一个 rid 并结束进程，
   **再点游戏图标重开**就是另一个角色（官方 8.0/16.9 也是按「一服一角色」做的）。
4. 新建角色（登录界面「+」）：`createrole` 会分配新 rid、写 profile、用登录模板补全存档
   （客户端只上传 ~320 字节的 bag+roledata，缺 level/pet 等块，直接回发会崩）。

实测：新建「长儿亦丝」→ 退出 → 重开仍在（`roles.json` 两条），
「切换角色」在两个档之间来回都正常。

## 4. 还没修：孙悟空被动吸血

`嗜血`（initiative_skill 1120）描述里的三条被动：+5% 吸血、+5% 暴击、提高暴伤。
技能已经装上（存档里 `skillindex` 会跟随拖动变化），但吸血仍然不生效。

已知线索：
- 吸血在子弹命中里是一次随机判定：`.rodata` 里有
  `YJEnemyBullet 击中目标－吸血随机%7f ---结果：%d`（0x1c3a1xx 附近），
  和暴击判定是同一段代码，`_refsall.txt` 里能直接查到引用地址。
- 暴击那一路的倍率来自子弹对象 `+0x580/+0x590` 两个「属性值」，
  吸血率大概率也在同一批字段里，可以照 `patch_crit_damage()` 的办法在垫片里改。

## 5. 构建命令（本轮）

```
# 1) 编译 dex（javac + d8）
powershell -File build.ps1 -NoRepack

# 2) 打补丁垫片（暴击 1.5 倍）
python _mk_shim_crit.py 1.5

# 3) base + 新 dex + 5孔 magic.sdb + 暴击垫片
powershell -File build_apk.ps1 -OutName fix172.apk -Libgame '' -Libtprt <path> -Install
```

- `-Libgame ''` 表示**不要**替换 libgame.so（必须保持原样，否则触发破解检测）
- `build_apk.ps1` 用 `_zipswap3.py` 只换指定条目（716MB 包 3 秒重写）
- 千万别用 `fix155/156` 那种 `Application=P` 的调试基底：进程在 nativeInit 后 exit(15)
