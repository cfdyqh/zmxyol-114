## 一、登录链：9game/UC 网页登录，且没有本地缓存

游戏渠道是 **7723**，但底层就是 **UC/九游 SDK**（prefs 里全是 `cn.uc.gamesdk.*`）。

抓到的登录请求：

```
GET http<path>
      ?app_id=1847&redirect_uri=htt<path>
      &deviceId=...&pGameId=539817&channelId=WM_73884&ve=9.8.12.0
```

页面（`v11/login_page.html`，5.4 KB）是一个普通表单：

```html
<form action="./user_9game.php?action=login&app_id=1847&pGameId=539817" method="post">
  通行证 / 密码 / 进入游戏
```

要点：

- **回调是 WebView 约定的 `htt<path> 在 WebViewClient 里拦这个 URL）。
- **没有本地会话缓存**：`cn.uc.gamesdk.pref.xml` 里没有 user id / sid，
  `YJMobileJNIHelper.getSDKUserID()` 只读内存静态字段 `f1444L1l`（由 `onLoginSucceed` 设）。
  → **每次启动都必须真实登录一次**（除非把登录也伪造掉）。
- 结论：**原包 + 本地服**这条路，卡点不在反外挂、不在协议，而在「9game 账号登录」这一下。

## 二、de-乐固路线：TP2 初始化不是 exit(15) 的原因

用 `cycle.ps1 -Tersafe ''`（**保留原版 libtersafe2**）+ 在 `OfflineInit` 里补了一次
TP2 初始化（反射 `com.tencent.tersafe2.TP2Sdk.init(19006)`，19006 = TP2 配置 URL
`iedsafe/Client/android/19006/config2.xml` 里的 app id）：

```
I YJOffline: data table refreshed: ...            ← EarlyBoot 全跑完
I YJOffline: offline server starting on 127.0.0.1:8077
I YJOffline: tp2 TP2Sdk.init(19006) -> 0           ← TP2 初始化成功
I YJOffline: patch: url[0/1/2] live                 ← 三个 URL 都改成 127.0.0.1:8077
I Zygote   : Process 15288 exited cleanly (15)      ← 仍然是 15
```

→ **TP2 初始化与否和 exit(15) 无关**（这个假设可以划掉）。

另外注意：`v11/java/.../LocalServer` 还是 **v8 的 Des（key `43((zmIp`）**，
现在 11.4.0 的 key/格式已经确定（`1#(z1Rr>` + `-=4399=-`），**必须先把 LocalServer
的编解码换掉**，否则就算过了 exit(15)，本地服也听不懂客户端。

## 三、libtprt 的 native 方法名是运行时解密的（影响后续 patch 方案）

反编译 `JNI_OnLoad @ 0x1326c`（`v11/ghidra/jnionload.txt`）：

```
memset(buf, 0, 0x400);
FUN_0001ceb4(env?, buf, 0x400);                 ← 把「方法名/签名表」解密到栈上 buf
RegisterNatives(env, cls, methods /*在栈上拼出来的*/, n /*DAT_00013310*/);
```

也就是说 `initialize`、`getGameId` 这些名字**不在 .rodata 里**（第一轮就发现搜不到），
是 `FUN_0001ceb4` 运行时解出来的。

→ 想在 libtprt 里定位「文件完整性校验」并 patch 掉，只有两条路：
1. 逆 `FUN_0001ceb4` 的解密（拿到明文方法名 → 顺藤摸到 `initialize` → 找校验点）；
2. 在**真机**上用 gdb/lldb 断 `RegisterNatives`，直接读出方法表（模拟器上不行：
   houdini 会 SIGILL，见第 3 轮 §四之二）。

## 四、现在的状态与岔路口

| 路线 | 现状 | 卡点 |
|---|---|---|
| 原包 + 本地服（root） | ✅ 过更新检查 → ✅ 资源加载 → ✅ 平台登录界面 | **9game 账号登录**（无本地会话） |
| de-乐固 + FnForce（真离线） | ✅ EarlyBoot/本地服/URL patch/TP2 init 全通 | **exit(15)**（nativeInit 处，机制仍未定位） |

两条路都需要下一步投入：

- 原包路线：把 9game 登录也吃掉（伪造 `user_9game.php` 登录 + 票据校验接口），
  或者先用真账号登录一次，把登录之后的所有业务请求录下来，再照着做本地应答
  （v800 的 `Canned.java`/`LocalServer.java` 里有现成的 `code:1000` 应答模板）。
- de-乐固路线：逆 `FUN_0001ceb4` → 找到 libtprt 的 `initialize` → 定位文件校验 →
  patch 掉；同时把 `LocalServer` 的编解码换成 DES-ECB/`1#(z1Rr>`。
