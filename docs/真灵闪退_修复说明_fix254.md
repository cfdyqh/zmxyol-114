# 11.4 离线版 · 进关卡第二次闪退（fix254）

> 2026-11-13 · 基于 `fix252.apk` 只换 `classes2.dex`
> 产物：`out\造梦西游OL-11.4-离线版-fix254.apk`（716,441,374 B，同签名，覆盖安装保档）

---

## 一、症状

- 第一次进关卡（`levelenter 700001` / 九重天 1-1）正常：能进图、能打、能出 `lvvictory`。
- 打完回城，客户端**自动再次** `levelenter 700001`（约 17 秒后），2~3 秒后闪退。
- 闪退点在 GLThread，tombstone 里 PC 落在 `libhoudini` / `[anon:Mem_0x20000000]`（ARM 翻译层），
  `signal 11 (SIGSEGV)`，`fault addr 0x128`，`Cause: null pointer dereference`。

## 二、根因（证据链）

1. 崩溃 tombstone 的栈里有一份构造出来的帧名：
   ```
   d22733b4  5f746570 ...   "pet_" "avatar" "ar_9" "005." "png\0"
   → "pet_avatar_9005.png"
   ```
   紧邻的返回地址是 `cocos2d::CCSpriteFrameCache::spriteFrameByName(char const*)+166`
   与 `cocos2d::CCSprite::setDisplayFrame(CCSpriteFrame*)+30`。
   ⇒ `spriteFrameByName("pet_avatar_9005.png")` 返回 NULL，
   `setDisplayFrame(NULL)` 解引用 `0x128` → SIGSEGV。

2. 服务端每份存档都会下发一只真灵 `dataid=9005`（`trueSpiritBag()` 默认值，
   `LocalServer.java` 登录分支里 `sd.put("truespiritinfo", tsList)`）。
   客户端把这只真灵当宠物画，头像帧名就是 `pet_avatar_9005.png`。

3. `assets/images/hd/interface/pet_avatar/pet_avatar.plist` 里确实有
   `pet_avatar_9005.png`，但**那份图集只有在打开宠物面板时才加载**：
   崩溃前的 `fopen` 日志里没有任何一次 `pet_avatar.plist`。

4. 为什么「第一次能进、第二次不行」：第一次进图时图集/纹理还在 cocos2d 缓存里；
   打完一关切场景会 purge 掉没被引用的纹理；第二次进图再取帧就拿到 NULL。
   （这一条是推断，与 1~3 的实测证据一致。）

## 三、改动

`v11\java\org\yjmobile\zmxy\offline\LocalServer.java` → `trueSpiritBag()` 开头加开关：

```java
if (!new java.io.File("/sdcard/yj/truespirit_on").exists()) {
    // 返回空 truespiritinfo，客户端不再创建真灵入口，也就不会再去找 pet_avatar_9005.png
}
```

- **默认不下发真灵**（这是修复）。
- 想再开回来：`adb shell touch /sdcard/yj/true_spirit_on` 后重启游戏（会再次闪退，仅用于继续排查）。

## 四、验证步骤

1. `adb install -r -d out\造梦西游OL-11.4-离线版-fix254.apk`（同签名，存档保留）。
2. 进游戏 → 进任意关卡 → 打完 → 回城 → **再进同一关**。
3. 期望：第二次进图不再闪退；`protocol.log` 里应看到连续多条
   `levelenter` / `lvvictory` 而没有新的 tombstone。
4. 兜底看日志：
   ```
   adb logcat -d -b crash | findstr "Fatal signal"
   adb shell ls -t /data/tombstones | head -1
   ```

## 五、回滚 / 备选

- 若 fix254 仍有问题，可退 `fix252.apk`（同签名，行为与 fix244 的差异只在服务端）。
- 用户原 fix244 存档备份（修复前导出）：
  - 设备：`/data/local/tmp/sv_base.json`、`/data/local/tmp/offline_backup/`
  - 本机：`$tmp\dev114\savedata_base.json`
- 参照包 `未经本人允许倒卖搬运户口本少两页.apk` 与 fix244 的差异只有 3 个文件：
  `lib/armeabi/libtprt.so`（= 本仓库 11/10 的 `libtprt-crit.so`，24052 B）、
  `assets/database/aura_ball.sdb`（33026 B，= `<tmp>/aura_patched.sdb`）、
  `classes2.dex`（238764 B，本仓库历史里没有对应构建）。
  它的 `trueSpiritBag()` 一样有 9005，所以「有没有真灵」不是它与 fix244 的差别。

## 六、本轮排除项（都有实测）

# fix255：本命神晋阶 + 四把仙剑规格

产物：`out\造梦西游OL-11.4-离线版-fix255.apk`（716,445,470 B，同签名，覆盖安装保档）
基线：fix252 + 新 `classes2.dex`（= fix254 的真灵改动 + 本节两项）

## 1. 本命神「晋阶」点了没反应

**原因**：服务端把 `fategod.degree` 写死成 0：

```java
if (raiseDegree) {
    used = takeBagItem(store, 503371, need);   // 命火照扣
    fg.put("degree", 0);                       // ← 等级永远是 0
}
```

客户端「当前等级：初阶0级」读的就是 `degree`，所以扣了 11 个命火却看不出任何变化。

**改动**（`fillFateGod`）：

- 先查包里的命火 `503371` 数量，够 11 个才扣；
- `degree = min(89, degree + 1)` 并随应答下发（客户端按 `fategod_raise_degree.sdb` 的
  grade 1..90 取属性加成，所以上限取 89）；
- 命火不够：**不扣材料、不改等级**，回 `state=1, msg=命火不足，需要 N 个`。

`sanitizeFateGod()`（登录/上传时跑）从「强制归零」改成「夹到 0..89」，
否则晋阶结果下一次登录就被抹掉。

> 上一轮把 degree 归零的理由是「进关卡 SIGILL」。这次限制在 0..89（表只有 90 行），
> 不再越界；如果实测进图仍崩，把 tombstone 发我。

## 2. 四把诛仙仙剑：10 阶 / 5 孔 / 五行金

| 字段 | 旧值 | 新值 | 说明 |
|---|---|---|---|
| `AV` | 10 | 10 | 阶数（10 阶） |
| `BG` | 1 孔开、其余 -1 | 5 个都 `BH=0` | 5 孔全开、空孔 |
| `AN` / `AO` | 2 / 0 | 2 / 0 | 五行显示：`(AN=2,AO=0)=金`（文档 §4.2 实测表） |
| `AQ` | 13（金\|水\|火） | **1（金）** | 五行位掩码，位序 金/木/水/火/土 |
| `AB` | 400 | 400 | 成长率 4.0 |

另外两点：

1. **老物品也会改**：新增 `normalizeSwords()`，登录下发存档前把背包里已有的这四把

   以前是全局单文件，只有第一个登录的角色能拿到四把剑，换角色就没有。
   仍然是「第二次登录」（`loginCount()>=2`）触发，包里已有的 id 不会重复发。
